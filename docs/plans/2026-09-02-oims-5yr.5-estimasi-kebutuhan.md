# Plan: Estimasi Kebutuhan Bahan (oims-5yr.5)

> PRD Tahap 2 §9. Issue `oims-5yr.5`, depends 5yr.3 + 5yr.4. **Dieksekusi langsung Claude.**

## Keputusan desain

- **Tanpa tabel baru** — kalkulasi on-the-fly di service, tampil sebagai section di halaman detail PO.
- BOM sumber: `po.bomId` (snapshot saat approve) ?? BOM aktif produk saat ini (untuk PO draft/preview).
- **Formula** (PRD §9, dua toleransi diterapkan berlapis):
  - pcs efektif per varian = `ceil(jumlahTarget × (1 + tolPO/100))` (= total rencana cutting)
  - per baris BOM: pcs applicable = Σ pcs efektif varian yang cocok `berlaku_ukuran` (null = semua ukuran, else match `varian.ukuran` case-insensitive)
  - kebutuhan standar = pcs applicable × kuantitas BOM; total = standar × (1 + tolBOM/100)
  - agregasi per bahan (bahan bisa muncul >1 baris BOM beda ukuran)
- Status per bahan: `tersedia` (stok ≥ total), `sebagian` (0 < stok < total), `tidak_tersedia` (stok ≤ 0). Kekurangan = max(0, total − stok).

## File

- `src/services/po-produksi.ts` — tambah `getEstimasiBahan(poId)`: join po_detail+varian, bom_detail+bahan+satuan, stok. Return rows + flag `bomVersi`/`bomNomor` + error kalau tak ada BOM.
- `/produksi/po/[id]/_components/EstimasiSection.tsx` — tabel: Bahan | Kebutuhan Standar | Toleransi | Total | Stok | Kekurangan | Status (badge). Pesan jelas kalau produk belum punya BOM aktif.
- Hook `useEstimasiBahan(poId)` di `usePoProduksi.ts`.
