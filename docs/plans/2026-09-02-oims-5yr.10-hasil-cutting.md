# Plan: Hasil Cutting (oims-5yr.10)

> PRD Tahap 2 §15. Issue `oims-5yr.10`, depends 5yr.8. **Dieksekusi langsung Claude.**

## Keputusan desain

- Hasil dicatat **bertahap**: satu WO boleh banyak dokumen hasil (per hari/batch). Nomor `CUT-YYYYMM-NNNN`.
- Kolom tersimpan per detail: `varian_id`, `jumlah_baik` int, `jumlah_rusak` int. **Derived**: total = baik+rusak; kurang/lebih = Σ(baik) vs target WO per varian (agregat lintas dokumen, tampil di rekap WO).
- Dicatat via **WO detail** (HasilSection): form modal per dokumen (tanggal + baris varian dari WO detail), list dokumen hasil + rekap agregat per varian (target | baik | rusak | kurang/lebih | progress).
- Hasil = sumber bundling (5yr.12): bundel hanya dari Σ baik − Σ sudah dibundel.
- Dokumen hasil final (tanpa edit); salah catat → hapus (soft, hanya kalau belum jadi sumber bundel — guard ditambah di 5yr.12) + buat ulang. Audit CREATE/DELETE.
- Guard: WO status harus sedang_dikerjakan/selesai_sebagian/selesai; baik+rusak ≥ 1 per dokumen.

## DDL (⚡ via MCP)

Tabel `hasil_cutting` (nomor unique, wo FK, tanggal, catatan, created_by, soft delete) + `hasil_cutting_detail` (hasil FK, varian FK, jumlah_baik int default 0, jumlah_rusak int default 0) + index.

## File

- `src/lib/schemas/hasil-cutting.ts`; service digabung `services/wo-cutting.ts`: createHasil, listHasil(woId), getRekapHasil(woId) (agregat per varian vs target), softDeleteHasil.
- `HasilSection.tsx` di WO detail — rekap agregat + list dokumen + modal catat hasil.

## Verifikasi

Catat 2 dokumen hasil → rekap agregat benar (kurang/lebih vs target); hapus dokumen → rekap turun; guard status WO. Audit terisi.
