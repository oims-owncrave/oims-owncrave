# Plan: Pemakaian Bahan Aktual + Rekonsiliasi (oims-5yr.9)

> PRD Tahap 2 §14. Issue `oims-5yr.9`, depends 5yr.8. **Dieksekusi langsung Claude.**

## Keputusan desain

- Satu baris = satu bahan per WO (unique partial wo+bahan). Dicatat/dikoreksi via modal di **WO detail** (bukan route sendiri) — pemakaian melekat ke WO.
- Kolom tersimpan: `jumlah_diterima`, `jumlah_digunakan`, `jumlah_sisa`, `jumlah_limbah`, `harga_rata_rata` (snapshot dari `bahan.harga_rata_rata` saat pertama catat — pola `barang_keluar_detail`). 
- **Derived (tidak disimpan)**: selisih belum dijelaskan = diterima − digunakan − sisa − limbah (rekonsiliasi PRD); nilai pemakaian = digunakan × harga; varians = digunakan − kebutuhan standar (dari `getEstimasiBahan(poId)` reuse).
- Prefill `jumlah_diterima` dari penerimaan cutting PO tsb (Σ jumlah_diterima per bahan) kalau ada.
- Update boleh (koreksi rekonsiliasi) + audit UPDATE; harga snapshot TIDAK berubah saat update.
- Guard: diterima/digunakan/sisa/limbah ≥ 0; digunakan+sisa+limbah ≤ diterima × 1.05 tidak dipaksa — selisih negatif ditampilkan merah saja (data lapangan bisa aneh, jangan blokir input).
- **Stok TIDAK disentuh di sini** — bahan sudah keluar dari gudang via barang keluar. Sisa kembali ke gudang = mutasi retur_masuk di 5yr.11 (issue berikutnya).

## DDL (⚡ via MCP)

Tabel `pemakaian_bahan` (wo FK, bahan FK, 4 kolom numeric, harga_rata_rata numeric(15,2), catatan, created_by, timestamps, soft delete) + partial unique (wo_id, bahan_id) WHERE deleted_at IS NULL + index wo.
