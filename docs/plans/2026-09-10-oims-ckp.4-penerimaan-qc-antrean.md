## Hulu — dari mana barang datang

Tahap 3 berakhir di `penerimaan_hasil_jahit_detail` (`src/db/schema.ts:1182`). Kolom kuncinya:


Komentar di schema (baris 1180) sudah menegaskan:

> `baik = baik VISUAL (bukan lolos QC — QC formal Tahap 4)`

Artinya **`jumlah_baik` = kandidat QC**, bukan barang lolos. Tahap 4 mengambil dari sini.
**JANGAN ubah tabel Tahap 3** — sambungannya memang sudah dirancang.

`jumlah_rusak` TIDAK masuk antrean QC (sudah ditangani `selisih_jahit` di Tahap 3).

## Task 2 — Modul rekap `src/lib/qc/rekap.ts`

Buat modul baru, **server-only tanpa `"use server"`** supaya bisa menerima `tx`
(persis pola `src/lib/jahit/rekap.ts` — buka file itu sebagai contoh bentuk).

```ts
import { sql } from "drizzle-orm";
import { penerimaanHasilJahitDetail } from "@/db/schema";

const h = penerimaanHasilJahitDetail;

/** Σ pcs dari baris ini yang SUDAH dikirim ke QC (header tidak dihapus). */
export const sudahKeQcSql = sql<number>`(
  SELECT COALESCE(SUM(d.jumlah_pcs), 0)::int
  FROM penerimaan_qc_detail d
  JOIN penerimaan_qc p ON p.id = d.penerimaan_qc_id
  WHERE d.penerimaan_hasil_detail_id = ${h.id} AND p.deleted_at IS NULL
)`;
```

Sisa siap QC = `h.jumlahBaik − sudahKeQcSql`. **Jangan simpan sebagai kolom.**

## Task 3 — Skip QC vendor (referensi §6)

Master vendor sudah punya `qcMode` (`qcModeEnum`, `src/db/schema.ts:144`, nilai
`internal | vendor`) sejak `oims-eba.1` — tinggal dipakai.

Aturan: penerimaan hasil jahit dari vendor dengan `qcMode = 'vendor'` **tidak muncul di
antrean QC internal** (QC sudah dilakukan di tempat vendor). Filter ini ada di query antrean:

```ts
.where(and(
  eq(vendor.qcMode, "internal"),
  sql`${h.jumlahBaik} - ${sudahKeQcSql} > 0`,
  isNull(penerimaanHasilJahit.deletedAt),
))
```

Di UI, baris vendor-QC ditandai badge "QC di vendor" pada halaman penerimaan hasil jahit
supaya operator tidak bingung mencarinya di antrean.

## Verifikasi

`pnpm tsc --noEmit` + `pnpm build` clean **bukan** verifikasi — ini soal aritmetika stok,
wajib dibuktikan lewat query DB (aturan `docs/claude/orchestrator-workflow.md` langkah 5).

Data uji Tahap 3 masih ada di DB (vendor `VDR-0001`, produk SMK, seri 9001).

1. Ambil satu baris penerimaan hasil dengan `jumlah_baik` > 0:
   ```sql
   SELECT d.id, d.jumlah_baik FROM penerimaan_hasil_jahit_detail d
   JOIN penerimaan_hasil_jahit p ON p.id = d.penerimaan_id
   WHERE p.deleted_at IS NULL AND d.jumlah_baik > 0 LIMIT 5;
   ```
2. Baris itu muncul di `/qc/antrean` dengan sisa = `jumlah_baik`.
3. Kirim sebagian (mis. 25 dari 30) → `IN-QC-YYYYMM-0001` terbuat, antrean **sisa 5**:
   ```sql
   SELECT d.jumlah_baik,
          COALESCE(SUM(q.jumlah_pcs), 0) AS sudah_ke_qc,
          d.jumlah_baik - COALESCE(SUM(q.jumlah_pcs), 0) AS sisa
   FROM penerimaan_hasil_jahit_detail d
   LEFT JOIN penerimaan_qc_detail q ON q.penerimaan_hasil_detail_id = d.id
   LEFT JOIN penerimaan_qc h ON h.id = q.penerimaan_qc_id AND h.deleted_at IS NULL
   WHERE d.id = '<id>' GROUP BY d.id, d.jumlah_baik;
   ```
4. **Guard**: coba kirim 10 lagi (sisa cuma 5) → **DITOLAK** dengan pesan jelas.
5. **Skip QC vendor**: ubah satu vendor jadi `qcMode='vendor'`, penerimaan hasilnya
   **tidak muncul** di antrean:
   ```sql
   UPDATE vendor SET qc_mode = 'vendor' WHERE kode = 'VDR-0001';
   -- refresh /qc/antrean → baris vendor itu hilang
   UPDATE vendor SET qc_mode = 'internal' WHERE kode = 'VDR-0001';  -- kembalikan
   ```
6. Umur antrean bertambah sesuai selisih hari dari tanggal terima.
7. Audit log terisi untuk `penerimaan_qc`.
