# Plan: Penerimaan Bahan oleh Cutting (oims-5yr.7)

> PRD Tahap 2 §11. Issue `oims-5yr.7`, depends 5yr.6. **Dieksekusi langsung Claude.**

## Keputusan desain

- **Dibuat dari Barang Keluar yang ter-link Permintaan Bahan** — PO otomatis dari rantai BK → PB → PO. BK tanpa PB tidak bisa diterima di sini (jaga rantai integrasi §2.7). Satu BK = satu penerimaan (guard existing).
- Prefill baris dari `barang_keluar_detail`: `jumlah_gudang` = kuantitas BK (locked), `jumlah_diterima` editable (default sama), `kondisi` enum per baris (baik/kurang/lebih/rusak/warna_tidak_sesuai/spesifikasi_tidak_sesuai), catatan per baris.
- **Selisih TIDAK disimpan** — derived `diterima − gudang` (tampil di detail).
- Tanpa kolom status header (pola transaksi Tahap 1: sekali simpan = final, koreksi lewat penyesuaian). Penyerah = createdBy BK (gudang), penerima = createdBy penerimaan (cutting) — tidak ada kolom duplikat.
- Nomor `PC-YYYYMM-NNNN` via `generateDocNumber` (extend "PC"/"penerimaan_cutting").
- Roles: create = owner+admin_produksi (cutting), read = semua.

## DDL (⚡ via MCP)

Enum `kondisi_terima`; tabel `penerimaan_cutting` (nomor unique, po FK, barang_keluar FK, tanggal_serah, tanggal_terima, catatan, created_by, soft delete) + `penerimaan_cutting_detail` (penerimaan FK, bahan FK, jumlah_gudang numeric, jumlah_diterima numeric, kondisi enum default 'baik', catatan) + index.
