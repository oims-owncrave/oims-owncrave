# Plan: PO Produksi (oims-5yr.4)

> PRD Tahap 2 §8. Issue `oims-5yr.4`, depends 5yr.2. **Dieksekusi langsung Claude** (deviasi: tanpa prompt Antigravity, permintaan Abu 2026-09-02).

## Keputusan desain

- **Nomor `PO-YYYY-NNNN`** (reset per TAHUN, sesuai PRD — beda dari dokumen lain yang YYYYMM). Helper lokal di service (COUNT LIKE + retry 23505), bukan `generateDocNumber`.
- **Status enum 11 nilai** sesuai PRD (`po_status`). Tahap 2B hanya pakai transisi: `draft → menunggu_persetujuan → disetujui → dibatalkan` (+ edit/hapus draft). Status cutting/bundling diisi flow Tahap 2C — TIDAK diupdate manual.
- **`bom_id` snapshot saat approve**: approvePo mengunci BOM aktif produk ke PO (estimasi & varians stabil walau BOM ganti versi). Approve DITOLAK kalau produk belum punya BOM aktif.
- `jumlah_target` **integer** (pcs produk utuh — aturan numeric hanya untuk uang & kuantitas bahan). `toleransi_persen` numeric per detail → total rencana cutting = ceil(target × (1+tol/100)) (computed, tidak disimpan).
- `prioritas` text (rendah/normal/tinggi/urgent — opsi fix di client). `jenis` enum `po_jenis` 6 nilai PRD.
- Roles: create/update/submit = owner+admin_produksi; approve/cancel = owner; read = semua.

## DDL (⚡ via MCP)

Enum `po_jenis`, `po_status`; tabel `po_produksi` (nomor unique, produk FK, bom_id FK nullable, tanggal mulai/target, prioritas, jenis, status, penanggung_jawab FK users, approved_by/at, soft delete) + `po_produksi_detail` (po FK, varian FK, jumlah_target int, toleransi numeric) + index po_detail_po_idx. Lihat `src/db/schema.ts` section Tahap 2.
