## Context

Master supplier = data pemasok bahan (PRD §8). Prerequisite `master bahan` (bahan bisa punya supplier utama) + `barang masuk` (transaksi dari supplier).

Schema `supplier` **sudah ada** (`src/db/schema.ts:67-77`) — JANGAN ubah:
```typescript
supplier: { id, kode (unique), nama, kontak, alamat, isActive, createdAt, updatedAt, deletedAt }
```
> PRD §8 sebut banyak field (telepon, email, kota, rekening, bank, termin) — schema hanya `kontak` + `alamat`. Ikut schema, skip field lain (jangan ubah schema di issue ini).

Aturan: nama wajib, kode unik, supplier yang punya transaksi tak boleh dihapus permanen → soft delete + guard, bisa nonaktif.

## Beda dari plan kategori

### Task 1 — Zod (`src/lib/schemas/supplier.ts`)
```typescript
import { z } from "zod";

export const supplierSchema = z.object({
  kode: z.string().min(1, "Kode wajib diisi").max(20),
  nama: z.string().min(1, "Nama wajib diisi").max(150),
  kontak: z.string().max(100).optional().or(z.literal("")),
  alamat: z.string().max(300).optional().or(z.literal("")),
  isActive: z.boolean().default(true),
});

export type SupplierInput = z.infer<typeof supplierSchema>;
```

### Task 2 — Server Actions (`src/services/supplier.ts`)
Sama pola kategori, dengan perbedaan:
- `tabel: "supplier"` di audit
- `listSupplier` order by `supplier.kode`
- Cek unik pakai `supplier.kode`
- Guard soft delete: cek `barangMasuk.supplierId`:
  ```typescript
  const used = await db.select({ id: barangMasuk.id }).from(barangMasuk)
    .where(eq(barangMasuk.supplierId, id)).limit(1);
  if (used.length > 0) return { error: "Supplier tidak bisa dihapus — punya transaksi barang masuk. Nonaktifkan saja." };
  ```
  (import `barangMasuk` dari schema; barangMasuk tidak punya `deletedAt` → cek tanpa filter deletedAt)
- Handle field optional: `kontak`/`alamat` string kosong → simpan `null` atau string kosong (konsisten, pilih string kosong → `undefined` di insert biar default null).
