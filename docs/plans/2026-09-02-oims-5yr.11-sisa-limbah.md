# Plan: Sisa Bahan + Limbah Cutting (oims-5yr.11)

> PRD Tahap 2 §16–17. Issue `oims-5yr.11`, depends 5yr.9. **Dieksekusi langsung Claude.**

## Keputusan desain

- **Sisa bahan** = record per (WO, bahan, jumlah, jenis) dengan status: `disimpan_cutting` (default) / `menunggu_gudang` / `diterima_gudang` / `dialokasikan` / `tidak_layak`.
- **Kembali ke gudang = satu-satunya jalur yang menyentuh stok**: aksi "Terima di Gudang" (owner/admin_gudang) → transaksi: status `diterima_gudang` + **append `mutasi_stok` tipe `retur_masuk`** + update cache `stok.kuantitas` (lock row, pola createBarangMasuk). Harga rata-rata TIDAK berubah (retur bukan pembelian). Kolom baru `mutasi_stok.sisa_bahan_id` untuk traceability (ALTER ADD COLUMN — schema change, bukan mutasi baris; append-only tetap terjaga).
- Status `diterima_gudang` = terminal (tidak bisa diubah/dihapus — sudah ada mutasi ledger).
- **Limbah cutting** = record per (WO, bahan, jumlah, jenis, penyebab, penanganan). `harga_rata_rata` snapshot saat catat → nilai kerugian derived = jumlah × harga. Foto: SKIP (belum ada infra upload — kolom tidak dibuat, tambah nanti kalau dibutuhkan).
- UI: dua section baru di WO detail hub (`SisaSection`, `LimbahSection`). Tanpa route baru.
- Roles: catat = owner+admin_produksi; terima gudang = owner+admin_gudang.

## DDL (⚡ via MCP)

Enum `sisa_jenis` (kain_utuh, potongan_besar, potongan_kecil, aksesoris_tidak_terpakai, bahan_berlebih), `sisa_status` (5 nilai di atas), `limbah_jenis` (potongan_kecil, kain_cacat, salah_potong, bahan_rusak, noda, sampah_produksi), `limbah_penanganan` (dibuang, disimpan, dijual, sampel, aksesori, retur_supplier). Tabel `sisa_bahan` + `limbah_cutting` (keduanya wo FK + bahan FK + jumlah numeric + soft delete). ALTER `mutasi_stok` ADD `sisa_bahan_id`.

## Verifikasi

Catat sisa → status disimpan; ajukan ke gudang → terima → mutasi retur_masuk muncul di ledger + stok naik + tidak bisa dihapus. Limbah: nilai kerugian = jumlah × snapshot. Audit semua aksi.
