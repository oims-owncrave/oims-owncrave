# Plan: WIP Cutting Derived + Dashboard Tahap 2 (oims-5yr.13)

> PRD Tahap 2 §20–21. Issue `oims-5yr.13`, depends 5yr.12. **Dieksekusi langsung Claude.**

## Keputusan desain

- **Status WIP = fungsi record turunan** (pola referensi §4), BUKAN kolom. Per PO aktif dihitung dari keberadaan/agregat record: PB → BK → penerimaan → WO → hasil → bundel:
  `menunggu bahan` (belum ada PB disetujui) → `bahan sudah keluar` (ada BK) → `menunggu diterima` → `bahan diterima` → `menunggu WO` → `sedang cutting` → `cutting selesai` (Σ baik ≥ target WO semua) → `sedang bundling` (ada bundel, belum semua) → `siap dikirim` (semua baik terbundel & ada siap_dikirim).
- Tanpa tabel baru — satu service `getWipCutting()` yang mengagregasi per PO (status PO disetujui..siap_jahit).
- Halaman `/produksi/wip`: kartu ringkasan (PO aktif, menunggu bahan, sedang cutting, hasil bulan ini, bundel siap kirim, limbah bulan ini — hitung dari query agregat) + tabel WIP per PO (nomor, produk, target, hasil baik, dibundel, status derived, umur hari).
- **Grafik PRD §21 DITUNDA** (target vs hasil per hari, efisiensi, dsb) — data historis belum ada; tambah setelah produksi jalan beberapa minggu. Kartu + tabel dulu.
- PO terlambat = targetSelesai < hari ini && belum selesai → badge merah di tabel.
