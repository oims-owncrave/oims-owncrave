# Plan: Bundling + Label (oims-5yr.12)

> PRD Tahap 2 §18–19. Issue `oims-5yr.12`, depends 5yr.10. **Dieksekusi langsung Claude.**

## Keputusan desain

- Satu bundel = satu varian (pola app lama): `wo_id` + `varian_id` + `jumlah_pcs` + `tujuan_penjahit` (text — master vendor baru ada di Tahap 3, nanti di-FK-kan) + `keterangan`.
- **Guard inti PRD**: jumlah bundel aktif per varian ≤ Σ hasil baik − Σ pcs sudah dibundel (transaksi + re-check). Bundel hanya dari WO yang punya hasil.
- Status `bundel_status`: `draft → siap_dikirim → sudah_dikirim` + `dibatalkan`. `sudah_dikirim` = immutable (diedit/dibatalkan TIDAK bisa) — transisi ke sudah_dikirim dilakukan flow pengiriman Tahap 3, di sini hanya draft/siap/batal.
- **Detail panel PRD (jenis panel, jumlah per pcs) DISEDERHANAKAN** jadi kolom `keterangan` text — app lama juga tanpa breakdown panel; tambah tabel detail nanti kalau owner butuh.
- **Label**: halaman print `/produksi/bundling/[id]/label` (logo teks + nomor + PO/produk + varian + jumlah + tujuan + tanggal, layout thermal-friendly, `window.print()`). **QR ditunda** — butuh package `qrcode` (dependency baru, tunggu konfirmasi Abu); area QR di label dikosongkan dulu.
- Guard tambahan di `softDeleteHasil` (5yr.10): tolak hapus dokumen hasil kalau sisa baik setelah hapus < total sudah dibundel per varian.
- Route `/produksi/bundling`: list + buat (modal dari list — pilih WO → varian → jumlah, tampil sisa bisa dibundel) + label. Nomor `BND-YYYYMM-NNNN`.

## DDL (⚡ via MCP)

Enum `bundel_status`; tabel `bundling` (nomor unique, wo FK, varian FK, jumlah_pcs int, tujuan_penjahit, keterangan, status, created_by, soft delete) + index wo.

## Verifikasi

Bundel melebihi hasil tersedia → ditolak dengan pesan sisa; hapus hasil yang sudah dibundel → ditolak; batal bundel draft/siap → pcs kembali bisa dibundel; label print rapi. Audit CREATE/UPDATE/CANCEL.
