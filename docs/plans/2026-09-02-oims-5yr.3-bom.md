# Plan: Bill of Materials — versi + satu aktif per produk (oims-5yr.3)

> PRD Tahap 2 §7. Issue: `oims-5yr.3`. Depends: `oims-5yr.2`.
> Pola UI: `docs/plans/_pola-master-crud.md`. Referensi halaman header+detail: barang masuk (`src/app/(with-layout)/inventory/barang-masuk/` + `src/services/barang-masuk.ts`).

## Konteks

BOM = resep bahan per produk (contoh PRD: Nordic Jacket M = 1,80 m Tactical Crinkle + 1,50 m AirMesh + resleting + label). Dipakai estimasi kebutuhan bahan PO (oims-5yr.5) dan varians pemakaian aktual (oims-5yr.9). Gap terbesar dari app lama — belum pernah ada implementasi referensi (referensi §10), jadi ikuti PRD ketat.

Keputusan desain:
- **Versi**: satu produk boleh banyak versi; hanya SATU `aktif` per produk (partial unique index DB). Perubahan pada BOM aktif/nonaktif = **buat versi baru** (copy detail → draft), BUKAN edit in-place. Draft masih boleh diedit.
- Status: `draft` → `aktif` (aksi "Aktifkan": nonaktifkan versi aktif lama + set `tanggal_berlaku` + `approved_by`, satu transaksi) → `nonaktif`.
- Satuan detail TIDAK disimpan — derive dari `bahan.satuanId` (aturan CLAUDE.md: satu bahan satu satuan).
- `toleransi_persen` numeric per baris (default 0). `berlaku_ukuran` text nullable — null = semua ukuran (cukup untuk sekarang; per-ukuran dipakai estimasi 5yr.5).
- Nomor `BOM-YYYYMM-NNNN` via `generateDocNumber("BOM", "bom")` existing (`src/lib/document-number.ts`).
- Route `/produksi/bom`: list → form halaman penuh `/produksi/bom/baru` (header + baris detail dinamis, pola barang masuk) + `/produksi/bom/[id]` detail read-only + aksi.

## Task 1 — DB Migration ⚡ CLAUDE VIA MCP (sudah selesai)

```sql
CREATE TYPE bom_status AS ENUM ('draft','aktif','nonaktif');
CREATE TABLE bom (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  nomor_dokumen text NOT NULL UNIQUE,
  produk_id uuid NOT NULL REFERENCES produk(id),
  versi integer NOT NULL DEFAULT 1,
  status bom_status NOT NULL DEFAULT 'draft',
  tanggal_berlaku timestamptz,
  catatan text,
  created_by uuid NOT NULL REFERENCES users(id),
  approved_by uuid REFERENCES users(id),
  approved_at timestamptz,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  deleted_at timestamptz
);
CREATE UNIQUE INDEX bom_satu_aktif_per_produk ON bom (produk_id) WHERE status = 'aktif' AND deleted_at IS NULL;
CREATE UNIQUE INDEX bom_produk_versi_unique ON bom (produk_id, versi) WHERE deleted_at IS NULL;
CREATE TABLE bom_detail (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  bom_id uuid NOT NULL REFERENCES bom(id),
  bahan_id uuid NOT NULL REFERENCES bahan(id),
  kuantitas numeric(15,3) NOT NULL,
  toleransi_persen numeric(5,2) NOT NULL DEFAULT 0,
  berlaku_ukuran text,
  keterangan text
);
CREATE INDEX bom_detail_bom_idx ON bom_detail (bom_id);
```

## Task 3 — Zod schema

`src/lib/schemas/bom.ts`:

```ts
import { z } from "zod";

export const bomDetailSchema = z.object({
  bahanId: z.string().uuid("Pilih bahan"),
  kuantitas: z.coerce.number().positive("Kuantitas harus > 0"),
  toleransiPersen: z.coerce.number().min(0).max(100).default(0),
  berlakuUkuran: z.string().optional(), // kosong = semua ukuran
  keterangan: z.string().optional(),
});

export const bomSchema = z.object({
  produkId: z.string().uuid("Pilih produk"),
  catatan: z.string().optional(),
  details: z.array(bomDetailSchema).min(1, "Minimal 1 bahan"),
});
export type BomFormValues = z.infer<typeof bomSchema>;
```

## Task 4 — Server Actions

`src/services/bom.ts` (pola transaksi lihat `src/services/barang-masuk.ts`):
- `listBom()` — join produk (kode+nama), `isNull(deletedAt)`, order createdAt desc. Kolom: nomor, produk, versi, status, jml bahan.
- `getBomDetail(id)` — header + details join bahan (kode, nama, satuan singkatan via join satuan).
- `createBom(values)` — transaksi: `versi = max(versi produk itu) + 1` (query max, bukan count), `generateDocNumber("BOM","bom")`, insert header (status draft, createdBy) + details, audit CREATE.
- `updateBom(id, values)` — HANYA kalau `status === 'draft'`, selain itu return error "BOM non-draft tidak bisa diedit — buat versi baru". Replace details (delete baris lama + insert baru dalam transaksi — bom_detail bukan ledger, boleh), audit UPDATE (before/after JSON).
- `activateBom(id)` — transaksi: set versi aktif lama produk itu → `nonaktif`; set target → `aktif`, `tanggalBerlaku = now()`, `approvedBy/At`; audit APPROVE. Guard: hanya dari draft.
- `deactivateBom(id)` — aktif → nonaktif, audit UPDATE.
- `createNewVersion(id)` — copy header (produk, catatan) + details → versi baru draft (pakai `createBom` logic internal), audit CREATE.
- `softDeleteBom(id)` — hanya draft; set deletedAt, audit DELETE.
