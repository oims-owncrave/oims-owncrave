# app-nkw.1 — Kontak per vendor: nama penerima jadi pilihan, bukan ketik bebas

**Tanggal:** 2026-09-22
**Beads:** `app-nkw.1` (P2), anak `app-nkw` (M3.2 serah terima)
**Asal:** jawaban Ucup atas pertanyaan no. 10 (`docs/pertanyaan-klien-18sep.md`)

---

## Kenapa ini dikerjakan

Ucup memilih **opsi (b)** dari tiga yang ditawarkan:

> *"Penting nama orangnya, soalnya kalo ada barang kurang/ilang nanti nanyanya
> ke orang itu."*

Dan kita sudah menjanjikan konsekuensinya di teks WA yang dikirim:

> *"Kalo (b), saya bikinin daftar orang per konveksi, tapi nanti kamu perlu
> daftarin dulu siapa aja orangnya di tiap konveksi."*

Sekarang nama penerima di surat jalan diketik bebas. Kalau barang kurang, nama
itu satu-satunya petunjuk siapa yang ditanya — dan teks bebas mudah salah tulis,
tidak konsisten, tidak bisa dicari.

### Master vendor TIDAK cukup — sudah diperiksa

`vendor` menyimpan **perusahaan**, dan kolom `kontak` di sana adalah **satu PIC
utama**, bukan daftar orang. Data dev membuktikannya:

| kode | nama | pemilik | kontak |
|---|---|---|---|
| VDR-0001 | CV Jahit Cibaduyut | H. Asep Saepudin | H. Asep |
| VDR-0002 | Konveksi Soreang Jaya | Ibu Nurhayati | Bu Nur |

`kontak` cuma panggilan akrab dari `pemilik` — satu orang per vendor. Yang
menerima barang di lapangan belum tentu pemiliknya.

## Keputusan desain

### 1. FK + snapshot nama, BUKAN FK saja

Ini konsekuensi langsung dari alasan Ucup memilih (b). Kalau surat jalan lama
hanya menyimpan FK, lalu orangnya dinonaktifkan atau namanya diperbaiki, **nama
di surat jalan lama ikut berubah** — dan bukti "siapa yang menerima waktu itu"
hilang. Padahal itu justru gunanya.

Jadi tiap kolom jadi **dua**:

```ts
kontakVendorId: uuid("kontak_vendor_id").references(() => kontakVendor.id), // nullable
penerima: text("penerima"), // snapshot nama saat transaksi — kolom yang SUDAH ADA
```

Kolom teks lama **dipertahankan**, isinya jadi snapshot. Pola ini sudah terbukti
di proyek ini: `penugasanJahitDetail.tarifSnapshot`.

### 2. Bukan halaman master baru — tab di Data Mitra

`master/data-mitra` sudah menampung 5 tab (Supplier, Vendor, Penjahit, Lokasi,
Tarif) hasil `app-z4wp`. Arah proyek sedang **mengurangi** jumlah entri master,
jadi menambah halaman ke-15 untuk daftar nama orang itu melawan arus.

Tapi Vendor dikelola lewat **modal** (`VendorFormModal`), bukan halaman detail —
jadi kontak tidak bisa jadi "seksi di halaman detail vendor" karena halaman itu
tidak ada.

**Keputusan: tab ke-6 "Kontak Vendor"** di `data-mitra`, isinya tabel semua kontak
dengan kolom Vendor + tombol tambah/edit/hapus. Filter per vendor lewat kolom.
Konsisten dengan lima tab lain yang semuanya berpola tabel + modal.

### 3. Dropdown tidak memblokir

Kalau vendor belum punya kontak terdaftar, form **tetap boleh disimpan** — pakai
`ComboSelect` yang bisa dikosongkan, dan kolom teks tetap terisi manual.
Pengiriman barang tidak boleh berhenti gara-gara master belum diisi.

### 4. Data lama tidak di-backfill

Nama yang terlanjur diketik manual **dibiarkan sebagai teks**. Menebak "orang ini
yang mana" dari teks bebas itu mengarang — dan snapshot-nya memang sudah benar
apa adanya. `kontakVendorId` untuk baris lama = `NULL`.

## Task

### Task 1 — DB migration ⚡ CLAUDE VIA MCP (bukan Antigravity)

```sql
CREATE TABLE kontak_vendor (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  vendor_id uuid NOT NULL REFERENCES vendor(id),
  nama text NOT NULL,
  jabatan text,
  telepon text,
  is_active boolean NOT NULL DEFAULT true,
  created_at timestamptz NOT NULL DEFAULT now(),
  updated_at timestamptz NOT NULL DEFAULT now(),
  deleted_at timestamptz
);
CREATE INDEX kontak_vendor_vendor_idx ON kontak_vendor(vendor_id);
CREATE UNIQUE INDEX kontak_vendor_nama_active_unique
  ON kontak_vendor(vendor_id, nama) WHERE deleted_at IS NULL;

ALTER TABLE pengiriman_jahit        ADD COLUMN kontak_vendor_id uuid REFERENCES kontak_vendor(id);
ALTER TABLE penerimaan_bundel_vendor ADD COLUMN kontak_vendor_id uuid REFERENCES kontak_vendor(id);
ALTER TABLE penerimaan_hasil_jahit   ADD COLUMN kontak_vendor_id uuid REFERENCES kontak_vendor(id);
```

**Partial unique WAJIB** (`WHERE deleted_at IS NULL`) — aturan CLAUDE.md: kolom
ber-`deleted_at` yang punya unique harus partial, kalau flat maka hapus lalu buat
ulang nama yang sama akan crash 500.

Dan untuk tiga kolom staf kita:

```sql
ALTER TABLE penerimaan_dekorasi  ADD COLUMN penerima_id uuid REFERENCES users(id);
ALTER TABLE penerimaan_qc        ADD COLUMN penerima_id uuid REFERENCES users(id);
ALTER TABLE transfer_barang_jadi ADD COLUMN pengirim_id uuid REFERENCES users(id);
ALTER TABLE transfer_barang_jadi ADD COLUMN penerima_id uuid REFERENCES users(id);
```

Lalu tambahkan `kontakVendor` ke `src/db/schema.ts` + 7 kolom FK di tabel terkait.

⚡ **Dieksekusi Claude saat sesi planning (dev + prod), `tsc` 0 error.
Antigravity mulai dari Task 2.**

### Task 4 — Tiga form pakai dropdown

| File | Field |
|---|---|
| `vendor/pengiriman/_components/PengirimanForm.tsx` | penerima (baris ~120 area) |
| `vendor/penerimaan/_components/PenerimaanForm.tsx:179` | `pengirimVendor` |
| serah terima bundel (cari pemakainya — `penerimaanBundelVendor`) | penerima |

Pola tiap field:

```tsx
<ComboSelect
  label="Penerima (orang konveksi)"
  clearable
  options={kontakOptions.map((k) => ({
    label: k.jabatan ? `${k.nama} — ${k.jabatan}` : k.nama,
    value: k.id,
  }))}
  value={watch("kontakVendorId") || null}
  onChange={(v) => {
    const id = (v as string) ?? "";
    setValue("kontakVendorId", id);
    // snapshot nama ikut terisi — inilah yang membuat surat jalan lama tetap terbaca
    const k = kontakOptions.find((x) => x.id === id);
    setValue("penerima", k?.nama ?? "");
  }}
/>
```

Dropdown **disaring per vendor yang dipilih di form itu**. Kalau vendor belum
dipilih, dropdown kosong dan kolom teks tetap bisa diisi manual.
